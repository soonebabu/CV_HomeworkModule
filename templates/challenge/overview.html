Challenge 1

Maintaining Narrative and Visual Consistency in Long-Form Generative Video

CSc 8830 Computer Vision. Challenge from Dr. Mohit Bansal's talk. This module is a quick prototype and feasibility test of the solution I proposed: a Scene-Graph Orchestrator that separates high-level narrative planning from low-level video generation.

Problem

Current generative video models make impressive short clips but fall apart over a long sequence:

  • Character drift: faces, clothing or overall appearance change between scenes.
  • Object & spatial shift: objects vanish or morph, and room layouts change for no reason.
  • Limited memory: the model forgets what happened in earlier scenes.
  • High prompt effort: keeping things consistent takes constant re-prompting.

Key question: how can we keep character, object and spatial state persistent across a long generated video?

How to use it

  1. Prototype run: pick or write a story and run it. You get the plan, the state graph after every scene, the adapter's conditioning, side-by-side baseline and orchestrator videos, and the scores. Takes about 10 s on CPU.
  2. Evaluate real clips: download the exported prompts from a prototype run, generate the clips with any text-to-video model (one clip per scene, once per prompt set), upload them, and get the same comparison measured directly on the real videos.
  3. Method & metrics explains every measurement, and Sample outputs has saved runs.

Expected result & feasibility

Result: less character drift and fewer disappearing objects in long-form video, with no loss of per-scene prompt adherence. The prototype measures exactly that difference.

Feasibility: nothing here is trained. The planner and judge are pretrained LLMs used as-is. The state graph and adapter are lightweight code that sits between them and a frozen generator, so any diffusion video model that accepts a prompt, a negative prompt, a seed and (optionally) layout boxes or a first frame can be plugged in without retraining.

Related work: the planner-then-generate design is in the same family as VideoDirectorGPT (LLM-guided multi-scene video planning, from Dr. Bansal's group). Here the plan is held as an explicit world state that persists and updates across scenes.
